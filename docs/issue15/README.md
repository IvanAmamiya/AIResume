# Issue #15 — 显式 A4 分页，fork 审阅稿

此分支仅推送 fork，不创建上游 PR。

## 改动与原理

原导出把整份长简历生成一张画布，再按 A4 高度裁切；根元素的 padding 不会在中间页重复。现在先生成独立 A4 页面，预览直接展示这些页面，导出逐页生成画布并放入 PDF，不再执行长图切片。

- `pageBoundaries.ts`：纯断点规划器。文字行与照片不可切；能装进一页的条目、段落、列表项和标题组合优先整体移动。过长段落按真实文字行拆分。可选避让无法前进时退回硬约束，不生成无限空白页。
- `paginateResume.ts`：在与最终页面相同的字体、宽度、样式祖先中测量 DOM。使用 Range 获取真实文字行包围框；处理首行字形超出 line-height，断点预留 1 px 抗锯齿空间。每页上下至少 10 mm；较大的用户上下间距继续保留。双栏分别计算断点，再组成同页。
- `ResumePages.vue`：等待异步模板、字体和图片，数据/语言/模板改变后重新分页；淘汰过期计算并在卸载时清理观察器。
- `exportResumePdf.ts`：按预览页面快照逐页渲染，直接写入 jsPDF；临时 DOM 无论成功或失败都清理。
- `resumePreview.vue`：接入分页组件和共享导出函数，导出期间避免重复点击并展示错误。
- `jspdf` 从原有间接依赖改为直接依赖，版本仍为 2.5.2，没有升级其他依赖。

分页 DOM 通过栏位克隆、位移及裁切窗口保留模板的富文本、链接和 scoped 样式。窗口边界来自安全文字行断点，不是 PDF 像素高度的盲切。当前每页保留整栏 DOM，超长文档的内存成本随页数增加；后续可在不改变可见结果的前提下裁减不可见节点。

## 测试结果（2026-10-13）

1. `npm test`：21/21 通过。其中 7 项分页单元测试覆盖单页、精确页高、小数坐标、短条目/标题避让、超长条目、避让无法前进、400 行的完整性、非法尺寸。另有 9 项流式解析和 5 项 i18n 回归。
2. `npm run test:browser:types` 与 `npm run build:prod`：浏览器测试入口、应用的 TypeScript 检查与生产构建通过。构建仍提示原有大 bundle。
3. 浏览器回归：5 个真实模板 × 3 种场景，15/15 通过。场景为默认示例、24 px 字体与 100 段中日英/emoji/粗体/链接混合长文本、12 px 字体与长 URL。逐页检查 A4 尺寸、重复页边距、可见文字行完整性与水平溢出、照片完整性；使用无裁切同栏位对照检查可见文字行数量与尺寸，防止遗漏或重复。具体输出见 `browser-results.txt` 和 `browser-results.png`。
4. 六页压力样本：浏览器内实际调用共享 PDF 生成函数，确认生成 6 页 A4，与预览一致。该检查不下载文件，不能代替 PDF 渲染后的逐页图片检查。
5. 实际两页 PDF：`double-column-after.pdf` 已下载并逐页渲染检查；第二页页首不再切字，有留白。该文件是修正字体继承后的中间验证样本，最终版本又增加了首行字形空间、1 px 安全距离及短段落避让，最终页面位置可能不同。不要把它标成最终 commit 的逐像素证据。

六页 PDF 下载曾被浏览器权限检查拒绝；用户明确允许后重试仍被拒绝，因此尚未完成该文件的离线逐页 PNG 检查。没有通过换下载路径或其他浏览器绕过。此限制不影响上述 15 组 DOM 回归与内存内 PDF 检查，但不能据此声称所有实际 PDF 图片都已检查。

## 本地复验

```sh
npm ci
npm test
npm run test:browser:types
npm run build:prod
npm run dev -- --host 127.0.0.1
```

打开 `/tests/pagination-browser.html`，点击 Run checks；再点 Validate six-page PDF in memory。允许下载时可用 Download six-page sample PDF 导出后检查所有页。这个入口仅由开发服务器提供，生产构建不打包测试页面。

## 范围与限制

- 已验证 Chromium 当前渲染环境；未验证 Firefox/Safari、打印机或任意外部自定义模板。
- 比页面内容区还高的单行或图片明确报错，不静默截断。
- PDF 仍为画布图片，正文不会因此变成可选中矢量文本。
- 标题和短条目避让可能留下较大空白；优先保留条目完整性。
- 此分支继承之前的流式修复、i18n 和模板排版提交。审阅分页本身请从 `5133807` 比较，不要把全部历史提交算成 #15 修改量。
